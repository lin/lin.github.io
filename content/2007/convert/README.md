# 高考等位分换算页 —— 数据与重新生成

这个文件夹里的 CSV 是页面的**唯一数据源**。改完任何一个，跑一次脚本，
`index.html` 就会重新生成。页面本身不读 CSV —— 数据在生成时被烤进 HTML，
所以**不跑脚本，改了 CSV 页面不会变**。

## 怎么重新生成

在仓库根目录：

```sh
python3 scripts/build-convert.py          # 生成
./scripts/build-convert.py --watch        # 盯着 CSV，一存盘就自动重新生成
python3 scripts/build-convert.py --check  # 只校验数据，不写文件
```

常用开关：

| 开关 | 作用 |
|---|---|
| `--watch` | 持续监视本文件夹的 CSV 与模板，改动即重建；Ctrl-C 结束。改坏了会打印错误但不退出，改回来就自动恢复 |
| `--check` | 只解析和校验，一个字节都不写。想确认数据没问题又不想动 `index.html` 时用 |
| `--quiet` / `-q` | 只打印警告和写入结果，省掉那一大段逐年概览 |
| `--strict` | 有 ⚠ 时以退出码 1 结束，方便挂到 CI 或 pre-commit |

每次会写两份**内容完全相同**的输出：

- `content/2007/convert/index.html` —— 和数据放在一起，可以直接双击用浏览器打开预览；
- `static/gaokao-convert/index.html` —— 站点发布用，线上地址是 `/gaokao-convert/`。

（`config.toml` 里把第一份从 Hugo 的内容管道里排除掉了，否则 Hugo 会把这个
自带 `<html>` 的独立页面再套一层主题模板，出来是坏的。）

## 各个 CSV 是什么

| 文件 | 列 | 说明 |
|---|---|---|
| `2004.csv` … `2026.csv` | 分数, 本段人数, 累计人数 | 一分一段表。文件名必须是四位年份，其他名字的 CSV 会被忽略 |
| `baselines.csv` | 年份, 清华分数线, 绥化市最高分, 绥化一中最高分, 上海交大分数线, 浙大分数线 | 录取线与当年最高分。最高分留空会自动用榜首补齐 |
| `suihuashi.csv` | 年份, 全市排名, 分数, 高中 | 绥化市历届前十，驱动位次图和「绥化市历届前十」表 |
| `suihua.csv` | 年份, 全校排名, 分数 | 绥化一中历届前十，驱动「绥化一中历届前十」表 |

一分一段表的写法各年并不统一，脚本按**表头名**解析，所以列的顺序无所谓：

- `累计人数` 和 `累积人数` 两种写法都认；
- 2009 年的列序是 `分数, 累积人数, 本段人数`，与其他年相反，照样能读；
- 2004–2009 是 CRLF 换行，无所谓；
- 2006/2009 表首那几行「累计人数为 0」的虚拟上限锚点会被自动剔除。

## 脚本会替你盯着的几件事

跑完看一眼输出，带 `⚠` 的行是数据本身对不上，脚本**不会替你猜谁对**，页面照现有
数据生成：

- **`suihua.csv` 与 `suihuashi.csv` 打架** —— 市榜里标着「绥化市第一中学」的学生，
  和校榜上的应该是同一批人。对不上就报，比如某年校榜记 673、市榜记 672。
  这两张表分别驱动页面上两个不同的区块，不一致的话同一个人会以两个分数出现在同一页上。
- **`baselines.csv` 的最高分与榜首打架** —— 比如 `绥化一中最高分` 写了 676，
  但 `suihua.csv` 那年的第 1 名是 681。
- **分母缺失** —— 2004/2006/2008 的表没到 150 分，没有「≥150 分的总人数」这个分母。
  这三年用的是脚本里写死的估计值（见 `ESTIMATED_TOTAL`），页面上会挂「分母估计」标签。

报错（`✗`）则是数据结构坏了，比如表头缺列、分数不是数字，这时不会写文件，
上一版 `index.html` 保持原样。

## 改了页面的样子怎么办

页面的 HTML/CSS/JS 在 `scripts/convert-template.html`，脚本把数据塞进模板里的
`__DATA__` 占位符。**要改样式或交互，改模板，别改生成出来的 `index.html`** ——
下次一跑脚本就被覆盖了。
